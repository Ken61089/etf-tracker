# 主動型 ETF 每日持股追蹤系統

每天自動抓取多檔台股主動型 ETF 的持股，比對出**買賣變化**與**跨 ETF 的共同／分歧動作**，
並抓**上市／上櫃投信買賣超一日排行**與 ETF 加減碼交叉比對，產生公開網頁儀表板。

## 資料來源（2026-10-07 起）

| 資料 | 來源 | 說明 |
|---|---|---|
| ETF 持股＋加減碼 | 籌碼小宇 `xiaoyu-etf.pages.dev/data/etf/<代號>.json` | 主來源。直接採用它算好的一日加碼／減碼／新增／出清（`wins.d1`）與估算金額（億）。單位是**張**（零股捨去） |
| ETF 持股（備援） | MoneyDJ | 小宇抓不到、或資料日期落後於已存最新快照時自動改用，加減碼由本系統自行比對 |
| 投信買賣超 | 富邦 DJ `zgk.djhtm?A=DD&B=0/1&C=1` | 上市（B=0）／上櫃（B=1）一日排行前 50，Big5 編碼；網頁只給月/日，年份由程式推算 |

- 小宇的 d1 基準日必須等於本系統前一份快照的資料日期才採用，否則自行比對（例如漏抓幾天）。
- 只要任一邊快照來自小宇，比對時兩邊都統一捨成「張」，避免零股差異變成假買賣。
- 投信快照存 `data/trust/<資料日期>.json`，上市、上櫃兩邊都抓成功才存。
- 交叉比對只拿「ETF 資料日期 = 投信資料日期」的 ETF，日期不同的會在頁面上註明。

## 儀表板有什麼

### 🤝 共同動作（第一個分頁）
跨 ETF 的法人共識分析，分三塊：
1. **🔴 多檔同步買進 / 新增** — 同一天有 ≥2 檔 ETF 一起買進的個股（新進場標 🆕）
2. **🟢 多檔同步賣出 / 剔除** — 同一天有 ≥2 檔 ETF 一起賣出的個股（出清標 ✖）
3. **⚖️ 分歧** — 同一檔同一天「有人買、也有人賣」的個股

每筆都列出**幾家、是哪幾家、各買賣多少股**。家數越多排越前面。
（共識門檻目前為 2 家，可調整。）

### 🏦 投信買賣超（第二個分頁）
1. **投信 × 主動 ETF 同向** — 投信買超且有追蹤的 ETF 同日加碼（或投信賣超＋ETF 減碼）的個股
2. **上市／上櫃投信買賣超一日排行** — 每列標出追蹤的 ETF 當天對該股的動作

共同動作分頁的個股旁也會標 🏦 投信買超／賣超張數。

### 各 ETF 分頁（每檔一頁，仿籌碼小宇）
可用「資料日」下拉選單／前一日、後一日切換最近 20 個資料日（各自對前一份比對）。
篩選鈕 **全部／新增／加碼／減碼／出清**（附檔數），清單可依市值、權重、張數排序。每列顯示：
- 市值（億）＝持有股數 × 當日收盤價、權重、持有張數
- 買N／賣N：追蹤的 ETF 中當天有幾檔加碼／減碼這檔
- 動作列：變化張數 · 買賣金額（億；最新一日用小宇數字，歷史日以成交均價估）· 權重變化
- 歷史日的收盤價／均價取自小宇，累積存在 `data/_prices/<代號>.json`（小宇只給近 61 日）

完整持股不在網頁上展開，每日快照存在 `data/`，CSV 封存在 `docs/archive/`。

> 顏色依台股慣例：🔴 紅＝買進／新增，🟢 綠＝賣出／剔除。

## 比對怎麼運作（重要觀念）

MoneyDJ 網頁**每次只顯示「最新一天」**的持股。能做到日對日比較，是因為：

> **每次抓取，系統就把當天快照存進 GitHub repo 永久保留**（`data/<代號>/<資料日期>.json`），
> 時間久了累積成一份自己的歷史資料庫。比對時拿「最新這份」對比「上一個**不同資料日期**的快照」。
> 網站只負責給今天，歷史是我們自己留的。

由此衍生的特性：
- **以「資料日期」為基準，不是日曆日**。ETF 持股延遲公布，同一天多跑幾次不會重複計算；週末／沒更新的日子會覆寫同一份，不會產生假變化。
- **需要 ≥2 個不同資料日期才會有比對結果**。第一次跑只有一份，會標示「首次建立基準」，等下一次資料日期更新後就自動出現變化。
- **萬一某天漏抓**，下次會拿最新對比「上次存到的那份」，呈現跨那幾天的淨變化；每張卡片都會標出**實際比對區間**（例如「對比 06-05 → 06-09」），完全透明。
- **歷史不會遺失**，每份快照都進版控永久保存。

## 自動更新（線上版）

已設定 GitHub Actions（見 `.github/workflows/update.yml`）：

- **台灣時間 18:00 起每小時**跑一次（cron UTC 10:00–17:00，共 8 個時段），直到各檔都更新到當日資料。任務具冪等性：沒有新資料日期就不存、不 commit，等於自動停。
- 之所以每小時：MoneyDJ 各檔更新時間錯開、且常落後，傍晚輪詢可在它更新到當日時就抓到。
- 排程時間不保證分秒準時（GitHub 免費排程尖峰可能延遲），push 失敗會自動 rebase 重試。
- 也可在 GitHub 的 **Actions 分頁 →「每日更新 ETF 持股」→ Run workflow** 手動立即觸發。

## 完整存檔（供人工比對）

為避免任何資料日期遺漏，系統採「**只要抓到沒存過的資料日期就一律存檔**」：

- 原始快照：`data/<代號>/<資料日期>.json`（版控永久保存）。
- 可下載的 CSV 封存：`docs/archive/<代號>.csv`，長格式（資料日期, 代號, 名稱, 投資比例%, 持有股數），
  可從網站直接下載，例如 https://ken61089.github.io/etf-tracker/archive/00981A.csv ，用 Excel 開即可自行比對任意兩天。
- 重新產生封存：`python3 etf_tracker.py --export`
- 若某來源資料日期仍落後於當日，儀表板該檔會標示「資料日期尚未更新到最新交易日」，但資料仍會完整存檔。

## 手動使用（本機）

最簡單：在 Finder 對 **`更新並開啟.command`** 點兩下 → 自動抓最新、產生儀表板並打開。

> 第一次點若出現「無法打開，因為來自未識別的開發者」，到
> 系統設定 → 隱私權與安全性 → 點「仍要打開」，之後就不會再問。

或用終端機：
```bash
cd ~/etf-tracker
python3 etf_tracker.py          # 抓最新資料 + 產生儀表板
python3 etf_tracker.py --build  # 不重抓，只用既有快照重產儀表板
open docs/index.html            # 開啟儀表板
```

本機手動與線上自動兩者並存、互不影響（僅需 Python 3 + curl，無第三方套件）。

## 怎麼加 / 移除 ETF

編輯 `etf_tracker.py` 最上面的 `ETFS` 字典，加一行 `"代號": "名稱",`（名稱隨意，會自動更新）：
```python
ETFS = {
    "00981A": "主動統一台股增長",
    # ... 加在這裡，例如：
    "00XXXX": "",
}
```
存檔後執行一次 `python3 etf_tracker.py`，再 `git add -A && git commit && git push` 即可。
（限 MoneyDJ 上「全部持股」格式相同的 ETF。）

## 容量與費用

- **線上網站固定約 84 KB**（只放最新一天，不會長大）。
- 每份快照約 4.4 KB、一個交易日（7 檔）約 31 KB。
- GitHub 歷史（.git）每年約成長 13 MB —— **約 78 年才會接近 GitHub 建議的 1 GB**。
- 公開 repo 的 Actions 免費無限分鐘、Pages 流量 100 GB/月。
- 結論：容量、流量、費用**幾十年內都不是問題，全程免費**。
